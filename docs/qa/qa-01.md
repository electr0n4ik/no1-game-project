# QA-отчёт №1 · нативное превью v0.3 → v0.4

Дата: 2026-08-24 · Тестер: агент · Устройство: Galaxy S25 Ultra (Android 16)
Метод: код-ревью боевого цикла + разбор жалоб игрока + логи heartbeat (Game tag).

## Жалобы игрока → найденные причины

| # | Жалоба | Корневая причина (баг) | Фикс в v0.4 |
|---|--------|------------------------|-------------|
| 1 | «Сразу погибает персонаж» | **B1** Спавн шёл КАЖДЫЙ КАДР (нет таймера) — 80 врагов за ~1.5 с вокруг игрока | Таймер `_spawnCd` по формулам спеки (0.8 c → 0.15) |
| 2 | «Враги слишком быстрые и их много» | **B2** Кольцо спавна сломано: радиусы X/Y считались раздельно (3.8–6.5u от игрока вместо края экрана) — враги появлялись вплотную | Единое кольцо `SpawnPos()`: r = max(halfW,halfH)+1.5u, кламп в арену, реролл ближе 6u |
| 3 | «Сразу погибают от одного касания» | **B3** Без глобальных i-frames окружение снимало 100 HP за ~1 с; плюс гиперспавн давал LVL-рывки урона | i-frames 0.5 с (по GDD) + отброс врага 0.12u от клинка; спавн-интервал убирает раш уровней |
| 4 | «Заходишь — и сразу игра, сразу поражение» | **B4** Тап в меню мгновенно стартовал кампанию (меню-блок в touch потерян), выживание недостижимо | Настоящие кнопки-плитки (рамка/заливка/хит-зона), отсчёт 3-2-1 перед стартом |
| 5 | Интерфейс | **B5** Нет паузы, смерть = «тапни в любом месте» | Кнопка паузы (в-бое), оверлей паузы (Продолжить/В меню), экран смерти с кнопками Заново/В меню |
| 6 | Все враги на одно лицо | **B6** Обычным врагам не проставлялся Sprite → все рисовались зомби | `Sprite = KindSprite(kind)` в Spawn |
| 7 | — | **B7** Нет телеметрии для QA | Heartbeat-лог раз в 10 с: t/hp/lvl/kills/mobs + DEAD-лог |

## Регресс-чек после фиксов (ожидания на устройстве)
- t=10 c: mobs ≤ 12, hp = 100 (грейс 3 c + интервал 0.8 c)
- t=30 c: mobs 15–35, hp > 60 при активном движении
- Спавн-точки: ≥ 6u от игрока (лог не пишем — визуально за краем экрана)
- Смерть раньше 25 c = провал баланса → тюнить `Spawn_Decay`/`Elite_*`
