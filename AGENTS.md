# AGENTS.md — правила работы с проектом «Рубилово» / no1-game-project

Обязательные к исполнению правила для любого агента и человека в этом репозитории.
Спорные случаи решаются в пользу спеки (`docs/spec/`), затем — в пользу тестов.

## 0. Главные принципы

1. **Спека → реализация → проверка → тест.** Любое изменение геймплея/экономики
   начинается с правки соответствующего документа `docs/spec/*.md`, потом код,
   потом верификация, потом тесты. Коммит без указания раздела спеки для
   геймплейных изменений не делается.
2. **Любое повторяющееся действие переносится в скилл.** Выполнил вручную
   одно и то же дважды (сборка, прогон, чеклист, публикация) — оформи
   `.opencode/skills/<имя>/SKILL.md` и дальше вызывай только его.
   Скилл = frontmatter `name` + `description` (триггерные слова!) + шаги командами.
3. **Коммит на каждой логической точке.** История читается как дневник работы:
   одна фича/фикс = один коммит, conventional commits (EN), тело — что и зачем
   со ссылкой на спеку (`Refs: docs/spec/01 §4`).
4. **Верификация обязательна до коммита.** Лестница проверки:

| Уровень | Что гоняем | Когда |
|---|---|---|
| V1 | `dotnet run --project tests/Logic.Tests` | любое касание `Assets/Scripts/Logic` |
| V2 | `dotnet build tests/SyntaxCheck/SyntaxCheck.csproj` | любое касание Unity-скриптов |
| V3 | GitHub Actions `tests` (required check на main) | каждый push/PR |

5. **Секреты никогда не попадают в репозиторий** (ключи подписи, UNITY_LICENSE,
   прод ad unit ID). Только GitHub Secrets / локальные файлы вне git.
6. **Ресурсы машины: сборки строго `-maxcpucount:6`** (из 12 потоков).
   Не грузить все ядра — комп должен оставаться отзывчивым. GPU в компиляции
   не участвует (тулчейн не умеет); GPU — только рендеринг игры на устройстве
   (`hardwareAccelerated=true`).

## 1. GitFlow

```
main      ← только release/hotfix-коммиты, protected: required check "Logic unit tests"
develop   ← интеграционная ветка, всегда собираемая
feature/* ← работа над задачей, ветвится от develop
release/* ← стабилизация версии перед вливанием в main (тег vX.Y.Z)
hotfix/*  ← срочный фикс поверх main, потом зеркалится в develop
```

Правила:
- **Прямые пуши в main запрещены** (кроме bootstrap/chore-документации).
- Фича: `git flow feature start <name>` ≡ `git checkout -b feature/<name> develop`.
- Завершение: PR `feature/<name> → develop`, squash-merge, ветка удаляется.
- Релиз: `release/x.y.z` из develop → мерж в main + тег → обратно в develop.
- APK собирается из тега main (GameCI) или локально (скилл `build-apk-local`).

## 2. Структура проекта

```
Assets/Scripts/Logic/   чистая C#-логика БЕЗ UnityEngine (тестируется dotnet)
Assets/Scripts/{Core,Player,Enemies,Ads,Meta,UI}/  Unity-слой
docs/spec/              ЕДИНСТВЕННЫЙ источник правды по дизайну (00–04)
docs/                   GDD, монетизация, чеклист публикации RuStore
native/Rubilovo.Android локальный APK-превью поверх Logic (без Unity)
tests/Logic.Tests       V1-тесты формул; tests/SyntaxCheck — V2 stub-компиляция
.opencode/skills/       скиллы повторяющихся действий (см. §3)
```

## 3. Реестр скиллов (`.opencode/skills/`)

| Скилл | Триггеры | Делает |
|---|---|---|
| `logic-tests` | «тесты», «формулы», «прогони логику» | V1-прогон dotnet |
| `syntax-check` | «проверь компиляцию», «синтаксис unity» | V2 stub-сборка всех скриптов |
| `build-apk-local` | «собери апк», «локально apk» | полный пайплайн локального APK |
| `gitflow-feature` | «новая фича», «начни фичу», «заверши фичу» | ветки/PR/squash по гитфлоу |
| `rustore-release` | «релиз», «публикация rustore» | чеклист выката версии |

При добавлении нового скилла — дополни эту таблицу тем же коммитом.

## 4. Definition of Done

- [ ] Спека обновлена (если менялся дизайн) — `Refs:` в коммите
- [ ] V1 зелёный; при касании Unity-слоя — V2 тоже
- [ ] Повторяющиеся ручные шаги вынесены в скилл и занесены в реестр §3
- [ ] CI на PR зелёный; squash-merge в develop/main

## 5. Коммуникация

- Пользователю отвечаем на русском, код/коммиты/CI — английские идентификаторы.
- Не коммитим артефакты сборок (`bin/`, `obj/`, `dist/`, `Library/`).
